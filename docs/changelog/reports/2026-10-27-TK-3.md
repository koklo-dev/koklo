# Period report — 2026-10-27 (TK-3, frontières entre paquets)

## Summary
Dependencies between workspace packages are now constrained by tags (`turbo boundaries`),
and deep imports (`pkg/src/...`) are refused. Both checks run in `pnpm lint`.

## Architecture and Runtime
`boundaries.tags` added to the root `turbo.json` (encodes CDC §16.4); `packages/config`
gets the tag `config` in its own `turbo.json`; new `src/check-deep-imports.ts` and
`src/deep-imports.ts`; root `lint` script extended. See
[architecture.md](../../architecture.md#package-boundaries-tk-3).

## Domain Model Changes
None.

## API and Tests
No API. `packages/config/test/boundaries.test.ts` with fixtures in
`packages/config/fixtures/boundaries/` covers both acceptance criteria (`domain`
depending on `db` fails `turbo boundaries`; a deep import is refused).

## Quality Gates and Fixes
`pnpm lint` now also runs `turbo boundaries` and the deep-import check. See
[quality-and-operations.md](../../quality-and-operations.md).

## Functional Impact
None for end users: developer tooling only, no screen. No functional guide or
screenshot written.

## Risks and Follow-ups
- A package without a `tags` entry is unchecked; each future package must declare its tag.
- The impact score recommended an ADR (boundary enforcement strategy); it was outside
  this pass's `impacted_docs`, so it is not written.
