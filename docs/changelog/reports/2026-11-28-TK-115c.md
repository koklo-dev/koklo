# TK-115c, 2026-11-28 : la version de la spec relue après une écriture

## Summary
Sur le staging, « Choisir » échouait avec « la spec a changé » et l'écran ne se mettait plus à jour avant un rechargement.

## Architecture and Runtime
Web seul. Après un enregistrement depuis la Relecture, `followIndex` relit `spec.head` jusqu'à la version écrite
(2 minutes au plus) puis relit la spec. Tant qu'un refus de version est affiché, `spec.head` est relu toutes les 5 s.
La protection du serveur (`stale_base`) est inchangée.

## Domain Model Changes
Aucun.

## API and Tests
Contrat inchangé. Nouveau fichier `apps/web/test/spec-write-stale.test.tsx` (5 cas, rouges avant le correctif).

## Quality Gates and Fixes
Tests web liés aux fichiers modifiés (92 fichiers, 1485 cas), nouveau fichier, typecheck web et `pnpm lint`.

## Functional Impact
« Recharger » sur « Choisir », « Marquer comme validée », le niveau ASVS et le résumé de la Sécurité ; ces actions sont
désactivées tant que la liste n'a pas rattrapé la dernière écriture.

## Risks and Follow-ups
La cause est déduite du code et du dépôt de spec, sans les logs du serveur. Une écriture venue d'ailleurs reste refusée
une fois, puis passe après « Recharger ». Choisir 16 options demande d'attendre l'indexation entre deux choix.
