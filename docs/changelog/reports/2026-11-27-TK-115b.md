# Rapport : TK-115b, stack proposée sur un grand projet (2026-11-27)

## Résumé
Sur un grand projet, l'agent découpe désormais la stack par couche pour que chaque réponse tienne sous le plafond de sortie ; les étapes écartées sont nommées avec leur motif ; le cahier technique ne se valide plus sans aucun choix de stack. Contrat 3.20.0, additif.

## Architecture et exécution
- Adaptateur du modèle : une réponse JSON coupée devient l'arrêt « max-tokens » (étape seule écartée « réponse coupée »).
- Worker : étapes calculées par code et bornées (Technique et Sécurité), contexte réduit à la couche, rôles dédoublonnés, bilan des étapes écartées.
- API : bilan rendu pour le Technique et la Sécurité ; refus `stack_missing`.
- Web : bilan en « étapes », « 0 choix · aucun pour l'instant », « Valider » désactivé avec sa raison reliée.
- Détail : `docs/architecture.md`, section TK-115b.

## Modèle de domaine
Aucun changement de schéma ni migration : `discarded_steps` est rangé dans la colonne jsonb existante.

## API et tests
Contrat 3.20.0 (`docs/api-contract.md`). Fichiers de test, motifs et diagnostic : `docs/quality-and-operations.md`. Résultats des verrous : journaux `.workflow/TK-115b/03-lot-A.md` et `03-lot-B.md`.

## Effet fonctionnel
Guides `review-and-complete-the-technical-specification.md`, `review-and-complete-the-security-deliverable.md` et `validate-the-spec.md`. Images : captures de `design/screens/captures/S-spec-technical/` et `S-spec-security/` (API simulée).

## Risques et suites
- La cause observée sur le staging n'est pas prouvée : aucun appel à un vrai modèle (B853).
- Un lancement propose au plus 30 choix et 4 à 8 étapes d'opérations ; une relance complète le reste.
- Recette sur le staging : redéployer api, worker et web ensemble ; relancer « Proposer avec l'agent » sur le grand projet ; relever les étapes écartées et leur motif ; vérifier que « Valider » reste désactivé sans choix de stack. Si « réponse coupée » persiste, porter le budget `proposal-batch` à 16 000 par un ticket (B844).
