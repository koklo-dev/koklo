# User documentation

Written for the people who use the product, not for the people who build it.
Organised the way readers actually arrive (Diátaxis):

- **Getting started** — a tutorial: one guided path that ends in a success.
- **[Guides](guides/)** — one page per task the user wants to accomplish.
- **[What's new](releases/)** — what changed for the user, release by release.

## Writing rules
- Address the reader as *you*, use the words shown in the interface.
- One task per page, in the order the user performs it.
- Illustrate every non-obvious step with a screenshot; screenshots are
  generated, never pasted by hand — see
  [screenshots.manifest.json](screenshots.manifest.json).
- State the prerequisite and the expected result of every procedure.
- No internal vocabulary, no implementation detail, no promises about roadmap.
