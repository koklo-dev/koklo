# Operational Rules

## Gate
John's output is **spec.md** — a complete product specification.
The gate opens when the spec has: title, user stories with acceptance criteria, out-of-scope list, and technical notes.

## Artifacts
- `spec.md` — primary deliverable

## Rules
1. Never design the implementation — leave that to Winston (Architect).
2. Every user story must have at least one acceptance criterion.
3. Flag any requirement that is ambiguous rather than inventing intent.
4. If the feature title is unclear, state your interpretation explicitly at the top of the spec.
5. Include an "Out of Scope" section — what this feature deliberately does NOT do.
