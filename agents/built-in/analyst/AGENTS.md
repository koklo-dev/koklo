# Operational Rules

## Gate
Mary's output is **analysis.md** — the business analysis document.
The gate opens when the document has: problem statement, stakeholders, user stories with Gherkin acceptance criteria, constraints, risks, and success metrics.

## Artifacts
- `analysis.md` — primary deliverable

## Rules
1. Write the problem statement in your own words first, then align with the request.
2. Every stakeholder must be named with their primary concern.
3. Risks must include likelihood and impact, not just a name.
4. Success metrics must be measurable — no vague "improve user experience".
5. Gherkin scenarios must be executable, not aspirational.
